# Обслуживание боевого сервера: обновление ОС и перезагрузка

Документ для человека без технической подготовки. Каждая команда — отдельный шаг:
скопируйте её целиком, вставьте в терминал сервера, нажмите Enter, дождитесь
конца вывода и сверьтесь с полем «Что должно получиться». Если результат не
совпал — **остановитесь** и переходите к разделу «Если что-то пошло не так».

* Сервер: Hetzner CX23, Ubuntu 24.04, каталог `/opt/agent-trade`, IP 46.224.52.105.
* Команды выполняются от вашего пользователя с `sudo`. Всё, что касается
  стека Docker, — от имени пользователя `agent` (`sudo -u agent …`) **из каталога
  `/opt/agent-trade`**.
* Время окна: **около 30–40 минут**, из них сам стек стоит 10–15 минут.

## 0. Когда это делать

* Окно — **08:00–10:00 UTC** (11:00–13:00 МСК). Не делайте перезагрузку в промежутке
  **03:00–06:30 UTC**: там работают ночные задачи (резервная копия, хранение,
  расчёты, суточная сводка, выгрузка), а по воскресеньям ещё очистка Docker и
  выгрузка копии наружу (04:00 и 04:30).
* Пока стек стоит, **данные не собираются**: минутная лента сделок и стакан за это
  время не восстановить, свечи биржа отдаёт задним числом. Открытые виртуальные
  позиции при этом не портятся: их состояние лежит в базе, а незакрытые бары
  разбираются после подъёма.
* Разово, при первом применении этапа 9.4, в это же окно входит применение
  настроек журналов Docker (шаг 6а).

## 1. Подготовка (стек ещё работает)

**Шаг 1.1. Зайдите на сервер и перейдите в каталог проекта.**

```
cd /opt/agent-trade
```
Что должно получиться: приглашение командной строки, ошибок нет.

**Шаг 1.2. Убедитесь, что ночные задачи сейчас не идут.**

```
pgrep -af "retention.py|backup_db.sh|remote_backup.sh|docker_gc.sh|barrier|baseline_main|trailing_main"
```
Что должно получиться: **пустой вывод**. Если что-то напечатано — подождите
5 минут и повторите. Перезагрузка посреди резервного копирования или свёртки —
плохая идея.

**Шаг 1.3. Проверьте свободное место (нужно не меньше 5 ГБ).**

```
df -h /
```
Что должно получиться: в колонке `Avail` не меньше `5G`.

**Шаг 1.4. Снимите слепок «до» (нужен, чтобы после перезагрузки доказать, что ничего не изменилось).**

```
sudo -u agent bash /opt/agent-trade/deploy/snapshot_9_4.sh before
```
Что должно получиться: в конце строка «Слепок записан в …/snapshot_9_4_before.txt»,
в строках нет слов `НЕ_СНЯТО`.

**Шаг 1.5. Сделайте свежую резервную копию базы.**

```
sudo -u agent /opt/agent-trade/scripts/backup_db.sh
```
Что должно получиться: последние строки «Бэкап готов: … » и «Готово.».

**Шаг 1.6. (Рекомендуется перед обновлением ОС) Снимок сервера в панели Hetzner.**
Откройте console.hetzner.cloud → ваш сервер → вкладка **Snapshots** → **Take
snapshot**. Это единственный способ полностью откатить обновление ОС (см. раздел
«Откат»). Снимок платный (несколько центов в месяц), после успешной проверки его
можно удалить.

## 2. Остановка стека

**Шаг 2.1. Выключите автоматический вотчдог.** Он каждые 10 минут поднимает
упавшие контейнеры и во время обслуживания мешал бы.

```
sudo mv /etc/cron.d/agent-trade /root/agent-trade.cron.disabled
```
Что должно получиться: пустой вывод. Проверка:
```
ls /etc/cron.d/
```
В списке **нет** файла `agent-trade`. **Запомните: его нужно вернуть на шаге 6.**

**Шаг 2.2. Остановите и уберите контейнеры стека.**

```
cd /opt/agent-trade && sudo -u agent docker compose --profile "*" down --timeout 60
```
Что должно получиться: строки «Container … Removed» по всем службам. **Никогда не
добавляйте к этой команде `-v`** — это удалило бы базу.

**Шаг 2.3. Убедитесь, что контейнеров не осталось.**

```
sudo -u agent docker ps
```
Что должно получиться: только заголовок таблицы, ни одной строки.

## 3. Обновление пакетов ОС

**Шаг 3.1. Обновите список пакетов.**

```
sudo apt-get update
```
Что должно получиться: в конце нет строк с `Err:` или `E:`.

**Шаг 3.2. Установите обновления.**

```
sudo DEBIAN_FRONTEND=noninteractive apt-get upgrade -y
```
Что должно получиться: команда завершилась без `E:`. Если появился синий экран
с вопросом — выберите вариант **keep the local version currently installed**
(оставить текущий файл), не меняйте настройки.

**Шаг 3.3. Нужна ли перезагрузка (справочно).**

```
ls /var/run/reboot-required
```
«No such file» — перезагрузка ядру не нужна, но в этом окне её всё равно делаем
(так применяются настройки Docker этапа 9.4).

## 4. Настройки журналов Docker (этап 9.4, один раз)

Пропустите этот раздел, если он уже выполнялся (`cat /etc/docker/daemon.json`
показывает `max-size`).

**Шаг 4.1. Слить настройки в `/etc/docker/daemon.json` (чужие настройки сохраняются).**

```
sudo python3 /opt/agent-trade/deploy/merge_docker_daemon.py
```
Что должно получиться: напечатан файл с `"log-driver": "json-file"` и
`"max-size": "20m"`, `"max-file": "3"`; рядом сохранена копия прежнего файла
`daemon.json.bak-…`, если он был.

Перезапускать docker отдельно не нужно: перезагрузка сервера сделает это сама.
Новые настройки применяются к контейнерам, **созданным после**, — поэтому в шаге 2.2
мы их именно убрали (`down`), а не остановили: при загрузке они создадутся заново
уже с ограничением.

## 5. Перезагрузка

**Шаг 5.1.**

```
sudo reboot
```
Соединение оборвётся — это нормально. Подождите 2–3 минуты и зайдите заново.

**Шаг 5.2. Проверьте, что сервер поднялся и стек стартовал сам (systemd).**

```
uptime -p && systemctl is-active docker agent-trade
```
Что должно получиться: `up 2 minutes` (или около того) и два слова `active`.

## 6. Возврат вотчдога и проверка живости

**Шаг 6.1. Верните расписание задач.**

```
sudo mv /root/agent-trade.cron.disabled /etc/cron.d/agent-trade
```
Проверка: `ls -l /etc/cron.d/agent-trade` — файл на месте, владелец `root`,
права `-rw-r--r--`. Если права другие: `sudo chmod 644 /etc/cron.d/agent-trade`.

**Шаг 6.2. Все службы работают.**

```
cd /opt/agent-trade && sudo -u agent docker compose ps
```
Что должно получиться: девять служб (`postgres redis collector agents decision notify
evaluator bot positions`), у всех состояние `running`, у имеющих проверку —
`healthy` (через 1–2 минуты после старта). `starting` в первую минуту — норма.

**Шаг 6.3. Настройки журналов применились (только при первом применении 9.4).**

```
sudo -u agent docker inspect --format '{{.Name}} {{.HostConfig.LogConfig.Type}} {{.HostConfig.LogConfig.Config}}' $(sudo -u agent docker ps -q)
```
Что должно получиться: у **каждого** контейнера `json-file map[max-file:3 max-size:20m]`.

**Шаг 6.4. Вотчдог видит порядок.**

```
sudo -u agent python3 /opt/agent-trade/scripts/watchdog.py
```
Что должно получиться: строки «Пороги диска: …» и последней — «Всё в норме. Действий
не требуется.». Если вотчдог написал, что поднимает контейнеры, подождите минуту и
повторите: сразу после старта это бывает.

**Шаг 6.5. Свежесть данных: возраст последней свечи.** Подождите **5 минут** после
старта и выполните:

```
sudo -u agent docker compose exec -T postgres psql -U agenttrade -d agenttrade -c "SELECT i.base, o.timeframe, now() - max(o.ts) AS age FROM ohlcv o JOIN instruments i ON i.id = o.instrument_id WHERE o.timeframe IN ('1m','1h') GROUP BY 1,2 ORDER BY 1,2;"
```
Что должно получиться: для `1m` возраст **меньше 3 минут**, для `1h` — **меньше 2 часов**
(время свечи — её начало) по каждому из пяти токенов.

**Шаг 6.5а. Отметки живости служб.**

```
sudo -u agent docker compose exec -T redis redis-cli --scan --pattern "*heartbeat*"
```
Что должно получиться: список ключей (collector, agent, decision, notify,
evaluator, bot, positions). Сверка их свежести — шаг 6.4 (вотчдог проверяет её сам).

**Шаг 6.6. Слепок «после» и сверка.**

```
sudo -u agent bash /opt/agent-trade/deploy/snapshot_9_4.sh after
```
Что должно получиться: три строки `OK` (`logic_version`, `agents_fingerprint`,
`positions_params_digest`) и код возврата 0. Число открытых позиций справочно: оно
может законно отличаться.

## Признак успеха

Все шесть пунктов выполнены: службы `running/healthy`, вотчдог «Всё в норме»,
свежесть свечей в норме, слепок «после» — три `OK`, (при первом применении 9.4)
журналы `max-size:20m`, cron возвращён.

## Признак неудачи

Любое из: служба не `running` через 5 минут; `docker` не запустился; вотчдог
непрерывно перезапускает одну и ту же службу; возраст `1m`-свечи больше 10 минут
через 10 минут после старта; в слепке «после» есть `РАСХОЖДЕНИЕ`.

## Если что-то пошло не так (откат)

1. **Docker не запускается после перезагрузки** (`systemctl is-active docker` не
   `active`) — почти всегда виноват `daemon.json`:
   ```
   sudo rm /etc/docker/daemon.json && sudo systemctl restart docker
   ```
   (или верните копию `daemon.json.bak-…` в `/etc/docker/daemon.json`). Затем
   `cd /opt/agent-trade && sudo -u agent docker compose up -d`.
2. **Стек не поднялся сам:**
   ```
   cd /opt/agent-trade && sudo -u agent docker compose up -d
   ```
   Причину смотрите: `sudo -u agent docker compose logs --tail 50 <служба>`.
3. **Служба падает после обновления пакетов** — откат пакетов вручную ненадёжен.
   Восстановите сервер из снимка Hetzner (шаг 1.6): Console → Snapshots →
   **Rebuild server from snapshot**. Данные базы после снимка будут потеряны — в
   этом случае восстановите их из копии в `/opt/agent-trade/backups` или из
   внешней копии Google Drive (`docs/STAGE_9_4_REPORT.md`, раздел «Восстановление»).
4. **Сервер не загружается вовсе** — Console → Rescue / Reset, затем снимок (п. 3).
5. Не забудьте вернуть вотчдог, если остановились на полпути:
   `sudo mv /root/agent-trade.cron.disabled /etc/cron.d/agent-trade`.

## Регулярное обновление без перезагрузки

Security-обновления ставятся автоматически (`unattended-upgrades`), но сервер
**не перезагружается сам**. Раз в месяц проверьте:

```
ls /var/run/reboot-required
```
Если файл есть — запланируйте окно по этому документу.
