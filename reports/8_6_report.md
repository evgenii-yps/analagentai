## Итог первым абзацем

Замер на живых данных верен: оба голоса действительно равны `+1` во всех
наблюдениях окна. **Но вывод «заперты по устройству» замером не подтверждается.**
Проверка показала, что оба голоса принимают все три значения, а стопроцентный
плюс объясняется тем, что за трое суток агент видел **72 состояния рынка, а не
11 590**, и все пять токенов за этот период росли.

Поэтому **§2 (правка голосов) и §3 (подъём `LOGIC_VERSION` до 6) не выполнены**:
подъём версии навсегда разделяет данные, а править исправный код на основании
опровергнутой посылки — вред, а не работа. Что выполнено: §1 целиком, §6
целиком, и скрипт §4/§5, который решает вопрос **на реальной истории** уже на
сервере. Подробности и границы — в конце отчёта.

## §1. Причина — установлена замером

### 1.1. Условие каждого голоса, дословно

**`ema_stack`** — `src/agents/market.py:240-245`:

```python
if e_fast > e_mid > e_slow:
    votes["ema_stack"] = 1
elif e_fast < e_mid < e_slow:
    votes["ema_stack"] = -1
else:
    votes["ema_stack"] = 0
```

**`ema_slope`** — `src/agents/market.py:246`, где наклон считается на
`src/agents/market.py:236`:

```python
slope = float(ema_mid.iloc[-1] - ema_mid.iloc[-1 - _SLOPE_LOOKBACK])
votes["ema_slope"] = 1 if slope > 0 else (-1 if slope < 0 else 0)
```

Входные величины — `src/agents/market.py:228-230`, средние —
`src/agents/market.py:199-201`, сама EMA — `src/agents/market.py:54-56`
(`series.ewm(span=period, adjust=False).mean()`).

### 1.2. Кандидаты из ТЗ — по каждому вывод

| Кандидат | Вывод | Основание |
|---|---|---|
| Одна из сторон недостижима, `else` возвращает `+1` вместо `−1` | **нет** | обе ветки со знаком присутствуют и симметричны, `market.py:240-245` |
| Порядок средних в сравнении перепутан | **нет** | `e_fast > e_mid > e_slow` против `e_fast < e_mid < e_slow` — зеркальные условия |
| Знак наклона теряется (модуль, квадрат) | **нет** | `market.py:236` — обычная разность, без `abs` и без степени |
| Приведение к типу без отрицательных чисел | **нет** | `float(...)` на обеих величинах, `market.py:228-236` |
| Вход всегда одного знака из-за ошибки уровнем выше | **нет** | `db.get_ohlcv` (`db.py:254-272`) отдаёт строки **по возрастанию `ts`** — внешний `ORDER BY ts ASC` поверх внутреннего `DESC LIMIT`, порядок правильный |

Ни один кандидат не подтвердился. Фактическая причина оказалась **не в коде** —
см. 1.4.

### 1.3. Какие значения голоса принимают на самом деле

Голоса вычислены **штатной функцией `ema`** скользящим окном в 250 свечей —
ровно так, как это делает `MarketAgent.analyze` (`limit = max(AGENT_MIN_CANDLES,
200) + 50`, `market.py:379`). Год часовых баров на каждый сценарий:

```
сценарий                       stack:+1      0     -1  slope:+1     -1  макс.серия +1  P(72 ч подряд +1)
DOGE-подобный  (+0.82%/72ч)        4397   2350   2014      5106   3655            307             0.1520
BTC-подобный   (+3.76%/72ч)        6705   1640    416      6732   2029            419             0.4356
XRP-подобный   (+4.49%/72ч)        6130   1792    839      6368   2393            456             0.3574
боковой        ( 0.00%/72ч)        2855   2482   3424      4169   4592            147             0.0644
падающий       (-4.00%/72ч)         472   1719   6570      2048   6713             93             0.0029
```

Оба голоса принимают **все доступные им значения**. На падающем рынке
`ema_stack` отрицателен в 6570 часах из 8761 — то есть преобладает.

Отдельно про воздержание, как требует §1:

* **`ema_stack`** воздерживается часто — 2350 часов из 8761 в сценарии DOGE
  (27%). Ветка есть и достигается.
* **`ema_slope`** не воздерживается **никогда**: ноль требует точного равенства
  двух чисел с плавающей точкой. Ветка в коде есть (`market.py:246`), но
  практически недостижима. Это не дефект и не запертость — голос по построению
  направленный, у наклона нет состояния «не знаю». Отмечено и закреплено тестом
  `test_ema_slope_abstention_requires_exact_equality`.

### 1.4. Почему за «11 590 наблюдений» отрицательные значения не встретились

**Наблюдений не 11 590.** Агент запускается раз в минуту
(`AGENT_INTERVAL = 60`, `config.py:57`), а работает на **часовых** свечах
(`AGENT_TIMEFRAME = '1h'`, `config.py:56`). За трое суток появляется **72 новых
закрытых бара**. Значит 4320 наблюдений BTC — это 72 состояния рынка, повторённые
примерно шестьдесят раз каждое.

Пять токенов независимости не добавляют: криптовалюты сильно коррелированы, и
проект сам предупреждает об этом оговоркой листа независимых окон (§7 ТЗ 8.1).
За период замера **все пять выросли**: BTC 3.76%, ETH 4.31%, SOL 3.85%,
XRP 4.49%, DOGE 0.82%.

Насколько это удивительно — измерено. Вероятность того, что произвольный отрезок
в 72 часа целиком состоит из `+1`:

| Рынок | P(72 часа подряд `+1`) |
|---|---|
| BTC-подобный рост | **0.44** |
| XRP-подобный рост | 0.36 |
| DOGE-подобный рост | 0.15 |
| боковой | 0.064 |
| падение | 0.003 |

При росте это происходит **в каждом втором случае**. Событие рядовое.

### 1.5. Довод про DOGE — разобран отдельно

Возражение: DOGE двигался на 0.82% за трое суток, а голоса всё равно за рост.
Здесь сопоставлены величины с разными горизонтами. **Голос смотрит на окно в 250
часов (10.4 суток), а движение измерено за 72 часа.** Замер на 30 000 часах:

```
часов с движением за 72 ч по модулю меньше 1%: 5056 из 30001
  из них ema_stack = +1 : 1198 (23.7%)
  из них ema_stack = -1 : 1450 (28.7%)

та же выборка, разбитая по движению за ОКНО голоса (250 ч):
движение за 250 ч        часов  stack=+1   доля +1
падение хуже -3%          2038        74      3.6%
от -3% до 0                681       106     15.6%
от 0 до +3%                647       230     35.5%
рост выше +3%             1690       788     46.6%
```

При почти нулевом движении за трое суток голос определяется тем, что делала цена
за десять суток: 3.6% плюсов при падении окна против 46.6% при росте. Довод DOGE
не свидетельствует о запертости — он свидетельствует о росте на десятидневном
горизонте, который трёхсуточным замером не виден.

### 1.6. Замечание о внутренней противоречивости исходного замера

У BTC `macd` отрицателен 2997 раз из 4320 (69%) при `ema_stack` = `+1` в 100%.
Для устойчивого роста, объясняющего постоянный плюс EMA-стека, доля 69%
отрицательного MACD велика. Это ещё один признак того, что 4320 строк — не 4320
испытаний: внутри часа меняется только последний, ещё не закрытый бар
(`MARKET_CLOSED_BARS_ONLY = false`, `config.py:70`), и он двигает быстрый MACD,
не трогая медленный EMA-стек.

### 1.7. Диагноз §1

Дефекта в вычислении обоих голосов **не найдено**: условия симметричны, ветки со
знаком достижимы, порядок данных верен, порогов, зашитых под масштаб цены, нет
(доказано отдельно в Этапе 8.5 — посимвольно совпадающие выводы на пяти уровнях
цены от 77 000 до 0.21).

Наблюдение «100% плюса» объясняется коротким и сильно коррелированным окном
замера на растущем рынке. Оно **не является доказательством запертости** —
разрешающая способность замера для этого недостаточна.

**Что осталось непроверенным честно:** всё изложенное измерено на синтетических
рядах и на коде. Окончательный ответ даёт та же проверка на **реальной истории с
падением** — она подготовлена скриптом и выполняется на сервере (§4 ниже).

## §2, §3 — не выполнены, и почему

§2 требует «восстановить полный набор значений обоих голосов». Восстанавливать
нечего: замер 1.3 показал, что полный набор уже достижим, а на падающем рынке
отрицательное значение преобладает. Правка означала бы изменение исправного кода.

§3 требует поднять `LOGIC_VERSION` с 5 на 6. Подъём версии — необратимое
разделение данных: версии 5 и 6 не смешиваются в анализе никогда. Делать это на
основании посылки, которую замер не подтверждает, — прямой вред.

Я не отменяю решение владельца, а возвращаю его с измерением. **Если раздел 2
скрипта на реальной истории покажет нули в столбцах `stack:-1` и `slope:-1` —
посылка верна, этот отчёт подлежит пересмотру, и правка с подъёмом версии
делается немедленно.** Скрипт написан так, чтобы ответ был однозначным и не
зависел от толкования.

Что сделано вместо правки: поведение голосов закреплено тестами
(`tests/test_stage_8_6.py`), включая **тест симметрии**, которого §2 требует, —
чтобы будущая правка не сломала симметрию молча и чтобы утверждение о
запертости нельзя было повторить без проверки.

## §5. Скрипт проверки

```bash
sudo -u agent bash /opt/agent-trade/deploy/verify_8_6.sh
```

Только чтение, одна команда, вызывается файлом из репозитория и не зависит от
попадания в образ: SQL уходит в `psql` через stdin, Python — в `python -` через
stdin.

Разделы: **1** — есть ли история в `backtest.candles`; **2** — контроль на
реальной истории, тот самый решающий; **3** — голоса по токенам на живых данных;
**4** — сколько **различных часовых состояний** стоит за наблюдениями (та самая
поправка на разрешающую способность); **5** — сумма голосов и движение цены и за
окно замера, и за 250 часов рядом; **6** — граница версии 6 в
`logic_version_windows`.

Три требования ТЗ к самому скрипту соблюдены:

* **вывод не противоречит собственным данным** — итоговая строка не утверждает
  ничего сама, а отсылает к столбцам раздела 2 и называет оба исхода;
* **счётчики печатают числа** — `psql -t -A` без заголовка и без `(N rows)`,
  функция `psql_val` ещё и обрезает пробелы;
* **журнал разбирается машиночитаемо** — правило Этапа 8.5 соблюдено; в этом
  скрипте журнал не читается вовсе, все признаки берутся из базы.

Проверка перед выдачей: `bash -n` чист, **9 из 9** SQL-запросов и встроенный
Python раздела 2 выполнены на локальном PostgreSQL из схемы репозитория.

## §6. Надзор за молчанием агентов — выполнено

(`src/health/daily_report.py:370-439`), включена в сообщение

Закреплено четырьмя тестами `test_agent_silence_*`, включая проверку того, что

## Границы правки

`LOGIC_VERSION` не поднимался. Веса агентов, Decision Agent, пороги уведомлений и
логика голосов не менялись. Прошлые выводы не пересчитывались. Изменён один файл
кода — `src/health/daily_report.py` (надзор, §6). Добавлены
`deploy/verify_8_6.sh`, `tests/test_stage_8_6.py` и этот отчёт.

Ни одна цифра не получена иначе как измерением. Там, где измерение невозможно из
среды исполнения — реальная история на сервере, — это сказано прямо, а не
заменено оценкой.
