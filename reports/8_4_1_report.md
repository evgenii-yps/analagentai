# Этап 8.4.1 — приёмник теряет ширину диапазона на листе независимых окон

**Ветка (проверена перед первым коммитом):** `claude/probability-targets-reconnaissance-ylg2co`

```
$ git branch --show-current
claude/probability-targets-reconnaissance-ylg2co
```

**Дата:** 2026-08-24. **Точка отсчёта:** `9e4ec67`.

---

## Что чинилось

Живая ошибка после пересборки образа 24.08.2026 15:35 UTC:

```
Exception: Die Spaltenzahl in den Daten stimmt nicht mit der Spaltenzahl im
Bereich überein. In den Daten sind es 15, im Bereich jedoch 1.
```

Приёмник `deploy/apps_script.gs` брал ширину диапазона записи как
`rows[0].length`. Первой строкой пачки листа «Независимые окна» идёт оговорка из
**одного** элемента (`src/export/transform.py:205-212`), заголовок и строки
данных — из **пятнадцати** (`transform.py:214-230`, `build_independent_row`).
Оговорка добавлена в Этапе 8.1, приёмник не менялся с 6.6.

Побочно ошибка сняла последнюю неясность Этапа 8.4: она доказывает, что
пересобранный образ несёт код репозитория. До пересборки отказа не было — это и
была причина расхождения, о котором отчёт `reports/8_4_report.md` сообщал как о
гипотезе A.

---

## Решение: ширина считается по набору, на обеих сторонах

Оговорка **не** подгонялась под пятнадцать колонок. Ширина нигде не задана
константой — она вычисляется как максимум по заголовку и всем строкам пачки,
поэтому следующее изменение состава колонок запись не сломает, а набор строк
разной длины стал штатным случаем.

### Сторона приёмника — `deploy/apps_script.gs`

```javascript
const width = maxWidth(rows, body.header);   // максимум по заголовку и всем строкам
if (width === 0) { /* пустая пачка — не отказ */ }
ensureColumns(sheet, width);                 // лист расширяется, если колонок мало
sheet.getRange(sheet.getLastRow() + 1, 1, padded.length, width).setValues(padded);
```

Короткие строки дополняются пустыми ячейками (`pad`), а не нулями: пустая ячейка
в таблице выглядит пустой, ноль выглядел бы значением. Добавлена константа
`RECEIVER_VERSION = '8.4.1'`, возвращаемая в ответе — по ней проверяется, что
развёрнутая версия обновилась (см. ниже).

### Сторона отправителя — `src/export/sheets.py`

Приёмник живёт на стороне Google и обновляется **вручную**, отдельно от образа.
Между пересборкой образа и обновлением скрипта есть окно, в котором работает
старая редакция. Поэтому пачка выравнивается ещё до отправки —
`normalize_batch`, вызывается в `post_rows`:

```python
rows, header = normalize_batch(rows, header)
```

Ширина считается тем же правилом (максимум по набору с учётом заголовка).
Порядок строк не меняется — оговорка остаётся первой.

**Следствие, проверенное стендом:** ближайшая выгрузка запишет лист без ошибки
**даже если приёмник ещё не обновлён**. Обновление приёмника нужно для
устойчивости в будущем, а не для того, чтобы разблокировать выгрузку сегодня.

Одна строка выравнивания покрывает все четыре листа: «Сигналы», «Сводка по
дням», «Независимые окна», «Корреляция токенов» — `post_rows` у них общий.

журнал следующей выгрузки — см. шаг 6 ниже.

## Как владельцу применить новую версию приёмника

Код приёмника живёт на стороне Google, в проекте Apps Script, привязанном к
таблице. Он **не** собирается вместе с образом и не обновляется деплоем сервера.

> **Осторожно, первым делом.** В файле репозитория на месте секрета стоит
> заглушка `ВСТАВЬ_СЮДА_СЕКРЕТ`. Если вставить файл целиком не глядя, рабочий
> секрет будет затёрт и выгрузка начнёт получать `forbidden`. Сначала скопируйте
> свой текущий секрет из строки `const SECRET = '…';`, потом вставляйте новый код.

1. Откройте таблицу «Agent Trade — Сигналы» в браузере.
2. Меню **Расширения → Apps Script**. Откроется редактор с файлом `Код.gs`
   (`Code.gs`).
3. **Скопируйте текущее значение секрета** из строки `const SECRET = '...';` в
   буфер или в заметку.
4. Выделите весь код в редакторе (Ctrl+A) и вставьте содержимое
   `deploy/apps_script.gs` из ветки `claude/probability-targets-reconnaissance-ylg2co`.
   В новой строке `const SECRET = 'ВСТАВЬ_СЮДА_СЕКРЕТ';` подставьте секрет из
   шага 3. Сохраните — **Ctrl+S** или значок дискеты.
5. **Развернуть → Управление развёртываниями** → у активного развёртывания
   нажмите **карандаш** (Изменить) → в поле **Версия** выберите **Новая версия**
   → **Развернуть**.
   Это важный шаг: без нового развёртывания адрес `/exec` продолжит отдавать
   старый код, сколько бы вы ни сохраняли редактор. Сам адрес `/exec` при этом
   **не меняется**, и `SHEETS_WEBAPP_URL` в `.env` править не нужно.
6. **Убедитесь, что применилось** — замером, а не на глаз. Запустите выгрузку
   вручную и посмотрите версию, которую сообщил приёмник:

   ```bash
   sudo -u agent bash -c 'cd /opt/agent-trade && docker compose --profile tools \
       run --rm --no-deps export' 2>&1 | tee /tmp/export_8_4_1.out \
       | grep -E 'receiver_version|Независимые окна|Служебные листы пересобраны'
   ```

   * `receiver_version=8.4.1` → новая версия развёрнута;
   * `receiver_version=до 8.4.1 (версию не сообщает)` → развёрнута прежняя;
     повторите шаг 5, скорее всего пропущено «Новая версия»;
   * строки `лист «Независимые окна»: …` быть не должно вовсе — её появление
     означает отказ записи.

7. Откройте лист «Независимые окна» и проверьте глазами то, что глазами и
   проверяется: первой строкой идёт заголовок, второй — оговорка, дальше данные.

Шаг 6 можно не делать вручную: ближайший запуск cron в 06:20 UTC напишет то же
самое в `/opt/agent-trade/logs/export.log`.

## Критерии приёмки

| Критерий ТЗ | Состояние | Чем подтверждено |
|---|---|---|
| Лист записывается без ошибки при данных любой ширины | выполнено | стенд, сценарии 1–3; ширина берётся по набору, не по первой строке |
| Оговорка присутствует первой строкой | выполнено | стенд, сценарий 1; тест `test_disclaimer_stays_first_row` |
| Тест на строки разной длины в одном наборе | выполнено | `test_ragged_batch_is_padded_to_widest_row`, стенд сценарий 2 |
| Все существующие тесты проходят | выполнено | 356 passed, 54 skipped |
| ruff чист | выполнено | `All checks passed!` |
| **В листе пять токенов и четыре горизонта** | **не измерено** | требует данных сервера; из среды исполнения продакшн-база недоступна. Проверяется разделами D и E `deploy/diagnose_8_4.sh` после успешной выгрузки |

Последний критерий не относится к ширине строк: состав листа задаётся отбором
строк, а отбор ТЗ 8.4.1 править запрещает. Отчёт `reports/8_4_report.md`
показал замером, что токен входит в ключ прореживания, то есть пять токенов
попадут в лист, как только у них появятся оценки. Сколько именно строк там
окажется — вопрос замера на сервере, и цифру без замера этот отчёт не называет.
