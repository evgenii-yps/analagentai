## 0. Резюме и главное ограничение среды выполнения

Задача состоит из трёх частей: (1) воспроизводимый прогон стека с нуля, (2) скрипт-аудит
доступности бирж, (3) отдельный вывод по DENT/USDT.

**Части 2 и 3 реализованы полностью как код + тесты.** Написан воспроизводимый скрипт
`scripts/exchange_audit.py`, схема хранения (`exchange_audit`, `pair_audit`), 32 теста с
замоканными ответами бирж (включая 451, таймаут, пустой стакан). Скрипт запускается одной
командой, проходит по всем 12 биржам и не падает целиком из-за одной недоступной биржи —
это подтверждено прогоном (см. §4).

**Живое исполнение частей 1 и 3 в текущей среде невозможно** — и это само по себе главный
результат этапа, зафиксированный как факт, а не обойдённый молча. Среда, в которой ведётся
разработка, — эфемерный контейнер с **egress-политикой, блокирующей весь внешний трафик,
кроме PyPI**. Проверено напрямую:

| Ресурс | Результат | Следствие |
|---|---|---|
| Docker Hub / registry (`docker pull redis:7-alpine`) | **403 Forbidden** | Образы не скачиваются → стек не поднять |
| Публичные эндпоинты бирж (OKX, Binance, …) | **403 на CONNECT** | Живой аудит и сбор данных невозможны |
| `api.telegram.org` | **403 на CONNECT** | Доставку в Telegram не проверить живьём |
| PyPI (`pip install`) | **OK** | Зависимости ставятся, тесты гоняются |
| Docker-демон | запущен | `docker compose config` валиден, но `up` упирается в pull |

Это ровно та ситуация, о которой предупреждает ТЗ: «всё проверялось только в эфемерной
среде без сохранения состояния». Данная среда — снова эфемерная и вдобавок с закрытым
egress. Поэтому **прогон 60 минут по BTC/USDT на OKX, замер `docker stats` и живая доставка
в Telegram должны выполняться на постоянном сервере (Hetzner)**. Ниже для каждого такого
пункта приведены точная команда и ожидаемая проверка. Фабриковать числа (число строк в
таблицах, пиковый RAM/CPU) было бы прямым нарушением п. 7 ТЗ — этого не сделано.

**Что реально выполнено и проверено здесь:**

  на аудит). Команда: `POSTGRES_PASSWORD=x python -m pytest -q` → `84 passed`.
- ✅ `ruff check` по новому коду — чисто.
- ✅ Скрипт аудита прогнан по всем 12 биржам, отработал без падения, корректно классифицировал

## 2. Часть 2 — Аудит доступности бирж

### 2.1 Скрипт `scripts/exchange_audit.py`

Реализовано ровно по сигнатурам ТЗ (§5.4):

- `check_exchange(exchange, source_ip_label, timeout_s=10.0) -> ExchangeAuditResult`
- `check_pair(exchange, symbol, source_ip_label, depth_band_pct=2.0, timeout_s=10.0) -> PairAuditResult`
- `run_audit(exchanges, symbols, source_ip_label) -> AuditReport`
- `render_report_markdown(report) -> str`

Свойства (все выполнены):

- **Одна команда, внутри Docker-сети:** `docker compose run --rm audit`
  (сервис `audit` под profile — не поднимается автоматически). Локально:
  `python -m scripts.exchange_audit --source-ip-label local`.
- **Только публичные эндпоинты**, никаких API-ключей.
- **Каждая биржа проверяется независимо** (`asyncio.gather(..., return_exceptions=True)`):
  падение одной не прерывает аудит — подтверждено тестом
  `test_run_audit_isolates_failures` и живым прогоном по 12 биржам.
- **Таймаут на запрос обязателен**, повтор **не более 2 раз** с экспоненциальной
  задержкой (`_get_with_retry`).
- **Три разных вердикта не смешиваются** — `classify_http_response`:
  - гео-блок → 451/403 или характерный текст (`STATUS_GEO_BLOCKED`);
  - rate limit → 429/418 (`STATUS_RATE_LIMITED`);
  - сетевая ошибка → соединение/таймаут/DNS (`STATUS_NETWORK_ERROR`);
  - плюс `STATUS_SERVER_ERROR` (5xx) и `STATUS_OK`.
- **HTTP-статус и задержка** снимаются напрямую (httpx) с эндпоинтов тикеров и списка
  инструментов — по обоим пишется строка в `exchange_audit`.
- **WebSocket** — через `ccxt.pro watch_ticker` (успешное подключение + первое сообщение).
  Использован ccxt.pro, **входящий в ccxt 4.4.100** → новая зависимость не потребовалась.

### 2.2 Аудит пар

По каждой доступной бирже проверяется список пар (параметр `--symbols`, по умолчанию
`BTC/USDT, ETH/USDT, SOL/USDT, DENT/USDT` — добавление пар без правки кода). Собираются:
листинг, последняя цена, лучшие bid/ask, спред %, глубина стакана в USD в пределах ±2 %
по обе стороны, объём 24ч в USD, tick size, минимальный размер заявки. Вердикт:

- `not_listed` — пары нет в `markets`;
- `illiquid` — спред > **0.3 %** ИЛИ глубина ±2 % с любой стороны < **50 000 USD**
  (или данные о ликвидности недоступны);
- `tradable` — иначе.

Пороги вынесены в `AuditConfig` (переопределяются через `AUDIT_SPREAD_MAX_PCT`,
`AUDIT_MIN_DEPTH_USD`, `AUDIT_DEPTH_BAND_PCT`), значения по умолчанию — из ТЗ. Пороги под
результат **не подгонялись**.

### 2.3 Схема хранения

Таблицы `exchange_audit` и `pair_audit` добавлены в `db/init.sql` (авто-применение на чистом
томе) **и** в `db.ensure_audit_schema()` (идемпотентно на существующем томе). DDL — точно по
ТЗ, включая `NUMERIC(28,14)` для цен: цена DENT ~0.0000277 требует запаса точности.
`source_ip_label` (`local` / `hetzner-nbg`) позволяет повторить аудит с сервера и сравнить —
гео-блокировки различаются по IP.

скрипта (сеть отличена от гео-блока), но не содержательная карта. См.

## 3. Часть 3 — Блок DENT/USDT

Три вопроса ТЗ реализованы в отчёте (`render_dent_block`) и функции
`notional_to_move_1pct` (сумма заявки на сдвиг цены 1 % по **фактическому** стакану, не
оценочно). **Числа даст только прогон с доступной сети** — в текущей среде их нет, и они не
выдуманы.

1. **Где листится DENT/USDT (среди доступных с текущего IP):** заполняется прогоном. По
   рынку пара ожидаема на OKX, Gate.io, MEXC, HTX, Bitget, XT, DigiFinex; подтвердит скрипт.
2. **Реальная ликвидность по каждой:** спред %, глубина ±2 % bid/ask, объём 24ч — колонки
   таблицы пар и блока DENT.
3. **Сумма заявки на сдвиг 1 %:** `notional_to_move_1pct(asks, bids, side)` идёт по уровням
   стакана, пока цена не пройдёт mid·(1±1 %), суммируя `price·amount`. Покрыто тестами
   (`test_notional_move_1pct_buy`, `..._insufficient_book`).

Команда для получения ответа на сервере:
```bash
docker compose run --rm audit \
  --symbols DENT/USDT --source-ip-label hetzner-nbg
```
